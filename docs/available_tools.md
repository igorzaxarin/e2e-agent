# Доступные инструменты GigaCode — обзор и оценка стоимости

Шкала стоимости (токены + задержка):
- 🟢 **Низкая** — сотни токенов, < 1 сек
- 🟡 **Средняя** — единицы тысяч токенов, секунды
- 🟠 **Высокая** — десятки тысяч токенов, десятки секунд
- 🔴 **Очень высокая** — отдельный LLM-контекст, минуты

---

## 1. Файловые инструменты

| Инструмент | Описание | Стоимость | Примечания |
|---|---|---|---|
| `list_directory` | Список файлов и подкаталогов каталога (с фильтрами .gitignore) | 🟢 | Дешёвый «первый взгляд» на структуру |
| `glob` | Поиск файлов по glob-шаблону (`**/*.py`) | 🟢–🟡 | Дешёв сам по себе; дорогой вывод при тысячах совпадений |
| `read_file` | Чтение файла: текст (с пагинацией), изображения (PNG/JPG/SVG…), PDF | 🟢–🟠 | Картинки и PDF заметно дороже текста; большие файлы усекаются |
| `write_file` | Запись/перезапись файла целиком | 🟡 | Стоимость ≈ объёму контента |
| `edit` | Точечная замена текста в файле (по уникальному фрагменту) | 🟢–🟡 | Дешевле `write_file` для правок; требует точного совпадения `old_string` |

## 2. Поиск по кодовой базе

| Инструмент | Описание | Стоимость | Примечания |
|---|---|---|---|
| `grep_search` | Контентный поиск (ripgrep, полноценные regex) | 🟢–🟡 | Быстрый движок; стоимость растёт с размером репозитория и числом совпадений |

## 3. Исполнение и сеть

| Инструмент | Описание | Стоимость | Примечания |
|---|---|---|---|
| `run_shell_command` | Выполнение bash-команд (есть фоновой режим, таймаут до 10 мин) | 🟢–🔴 | Стоимость определяется командой: `ls` — копейки; сборка/тесты — десятки секунд; весь stdout попадает в контекст |
| `web_fetch` | Загрузка URL + обработка содержимого быстрой моделью по промпту | 🟠 | Сетевая задержка + LLM-обработка; большие страницы суммируются |
| `skill` | Запуск навыка: `mcp-atlassian` (Jira/Confluence/Bitbucket), `review` | 🟡–🟠 | Сам навык дёшев, но тянет за собой цепочку MCP-вызовов |

## 4. Оркестрация диалога

| Инструмент | Описание | Стоимость | Примечания |
|---|---|---|---|
| `todo_write` | План и трекинг задач (статусы pending/in_progress/completed) | 🟢 | Чистая дисциплина, почти бесплатна |
| `ask_user_question` | Вопрос пользователю с вариантами ответа | 🟢 (токены), ⏸ блокирует | Выполнение останавливается до ответа человека |
| `exit_plan_mode` | Выдача плана на одобрение (только в plan mode) | 🟢 (токены), ⏸ блокирует | Аналогично — ждёт подтверждения |
| `save_memory` | Сохранение факта в долговременную память (`~/.gigacode/GIGACODE.md` или проекта) | 🟢 | Персистентно между сессиями |

## 5. Суб-агенты (`agent`) — самый дорогой ресурс

Запуск суб-агента = **отдельная LLM-сессия со своим контекстом и своим циклом инструментов**.
Результат возвращается одной сводкой в основной диалог. Агентов можно запускать
параллельно (несколько вызовов в одном сообщении).

| Суб-агент | Назначение | Стоимость |
|---|---|---|
| `Explore` | Быстрый поиск/разведка кодовой базы (уровни quick/medium/very thorough) | 🔴 (но дешевле ручного многошагового поиска в основном контексте) |
| `general-purpose` | Универсальные многошаговые задачи: исследования, сложный поиск | 🔴 |
| `requirements-analyst` | Требования → планы сьют (journey) + `_index.json` | 🔴 |
| `qa-designer` | Написание e2e тест-кейсов (Markdown + JSON) по плану сьюты | 🔴 |
| `test-critic` | Ревью кейсов: BLOCKER/MAJOR/MINOR + список исправлений | 🔴 |
| `pytest-test-writer` | Генерация pytest-тестов из кейсов (фаза 4) | 🔴 |

**Экономика:** один вызов суб-агента ≈ десятки тысяч токенов и минуты работы.
Выгоден, когда задача многошаговая (сэкономленный контекст основного диалога
перевешивает), невыгоден — для одного `read_file` или точечного grep.

## Сводка по «тяжести»

| Класс | Инструменты |
|---|---|
| Почти бесплатные | `todo_write`, `save_memory`, `list_directory`, `ask_user_question` |
| Дешёвые при умеренном использовании | `glob`, `grep_search`, `edit`, `read_file` (текст) |
| Умеренно дорогие | `write_file`, `web_fetch`, `skill`, `read_file` (PDF/изображения) |
| Широкий диапазон | `run_shell_command` (от `ls` до полного прогона тестов) |
| Максимальные | `agent` (любой суб-агент) — отдельный контекст, минуты |

## Практические правила экономии

1. Точечный поиск — `glob`/`grep_search` вместо `Explore`-агента; многоэтапная разведка — наоборот, агент.
2. Правки — `edit` вместо перезаписи файла `write_file`.
3. `read_file` с `offset`/`limit` для больших файлов вместо чтения целиком.
4. Независимые вызовы — пакетом в одном сообщении (параллелизм без лишних ходок).
5. Объёмный stdout команд перенаправлять в файл и читать выборочно.

## Матрица: какой агент чем пользуется

Выдача урезана по принципу наименьших привилегий — инструмент, который спека агенту не
предписывает, ему не выдан. Лишний инструмент не бесплатен: слабая модель выбирает из того,
что видит, и дорогая операция выбирается тем чаще, чем она доступнее.

| Агент | Инструменты | Чего нет и почему |
|---|---|---|
| `requirements-analyst` | `read_file`, `read_many_files`, `write_file`, `run_shell_command` | `ask_user_question` — под-агент не спрашивает, его вопросы уходят в `_index.json` и всплывают на шлюзе требований |
| `qa-designer` | + `grep_search` | `edit` — правки идут через `patch_case.py` (fail-closed); две дороги к одной операции слабая модель путает |
| `test-critic` | `read_file`, `read_many_files`, `write_file`, `run_shell_command` | — |
| `ui-cartographer` | то же | — |
| `pytest-stub-writer` | то же | `edit` — пишет файлы с нуля |
| `browser-test-writer` | + `edit` | — |

Снято у всех: `glob` (пути агентам даются явные, шаблоны принимает сам `read_many_files`),
`grep` (такого имени нет — правильное `grep_search`, и нужно оно только дизайнеру при
перенумерации шагов), `ask_user_question` у аналитика.

Не выдавалось никогда и выдаваться не должно: `agent` (под-агент, порождающий под-агентов,
множит 🔴 без потолка), `save_memory` (переносит состояние между прогонами — прогон обязан быть
воспроизводимым), `web_fetch` (адрес, который человек не называл для этого прогона, — обращение
к постороннему сервису), `todo_write` и `exit_plan_mode` (оркестрация чужого уровня).

## Операции, предписанные спеками

Правила экономии выше — общие. В спеках они стоят там, где агент реально несёт их стоимость:

| Операция | Кому предписана | Вместо чего |
|---|---|---|
| одно пакетное чтение всех входов | всем шести | N вызовов `read_file`, каждый через весь выросший контекст |
| `edit` для дополнения чужого файла | `browser-test-writer` (3 файла) | `write_file` — перепечатка файла целиком |
| `patch_case.py` на фикс-итерации | `qa-designer` | `write_file` — печать кейса целиком ради одной строки |
| вывод pytest в файл + `tail` | обоим писателям | полный лог прогона в контексте |
| `read_file` с `offset`/`limit` по большому файлу | `ui-cartographer` (инвентарь), писателям (логи) | перечитывание с начала |
