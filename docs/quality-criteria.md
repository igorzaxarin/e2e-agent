# Критерии качества

Каждый выпущенный кейс оценивается по 12 критериям. Критик обязан вынести вердикт по каждому.

| # | Критерий | Что проверяется | Как проверяется |
|---:|---|---|---|
| 1 | Полнота сквозного сценария | Покрыт весь пользовательский путь от начала до конца | Первый шаг — вход в путь, последний — достижение цели journey; ни один этап suite-плана не пропущен |
| 2 | Логическая связность | Шаги образуют единый сценарий, а не набор проверок | Каждый шаг зависит от состояния, созданного предыдущими |
| 3 | Корректность предусловий | Указано начальное состояние пользователя, аккаунта и данных | Предусловия достаточны для выполнения шага 1 без домыслов |
| 4 | Качество тестовых данных | Данные конкретны, достаточны и не противоречат сценарию | В таблице данных нет плейсхолдеров, все значения используются |
| 5 | Атомарность шагов | В одном шаге не объединено несколько действий | Один глагол действия на шаг |
| 6 | Проверяемость результатов | Конкретный и наблюдаемый результат для каждого шага | Нет запрещённых расплывчатых формулировок |
| 7 | Покрытие состояний | Проверяются изменения данных, авторизации, плеера, очереди, плейлистов | Изменения состояния явно проверяются, а не подразумеваются |
| 8 | Работа с неоднозначностями | Выявлены пробелы и противоречия требований | Раздел пробелов не пуст, если требования неполны |
| 9 | Качество уточняющих вопросов | Вопросы конкретны и устраняют неопределённость | Вопрос адресный, ответ на него меняет шаги кейса |
| 10 | Отсутствие выдуманных функций | Нет поведения, которого нет в требованиях | Каждый ожидаемый результат трассируется до REQ-XX |
| 11 | Переиспользуемость | Формат применим не только к текущему продукту | В шаблонах и промптах нет доменных допущений |
| 12 | Структурированность | Результат соответствует шаблону | Линтер `scripts/validate_cases.py` проходит без ошибок структуры |
