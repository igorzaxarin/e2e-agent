# Бизнес-требования к веб-версии музыкального сервиса «Звук»

## 1. Бизнес-контекст и проблема

Пользователи веб-версии музыкального сервиса «Звук» ожидают непрерывного доступа к музыке, персональной библиотеке, плейлистам и истории прослушивания в рамках одной и нескольких пользовательских сессий.

Пользовательский путь включает:
- авторизацию по номеру телефона;
- работу с рекомендациями;
- поиск музыки;
- просмотр страниц исполнителей и альбомов;
- воспроизведение;
- управление плеером;
- сохранение музыки;
- создание и редактирование плейлистов;
- формирование очереди;
- выход и повторный вход в аккаунт;
- восстановление ранее сохранённого состояния.

Поведение сервиса различается для пользователей с активной подпиской и без неё. Требования должны обеспечить предсказуемую работу сервиса на всех этапах длинного пользовательского пути и корректное сохранение пользовательских данных между сессиями.

Текущие требования описывают существующее поведение сервиса и отдельные целевые изменения.

Целевым изменением является улучшение повторной авторизации и восстановления пользовательского состояния после входа в тот же аккаунт.

### 3.1. Приоритетные пользовательские пути (P0)

### 3.2. Базовые функциональные требования

| ID | Бизнес-требование | Детализация | Приоритет |
| :--- | :--- | :--- | :--- |
| **BR-001** | **Авторизация пользователя** | **Тип входа:** пользователь входит по номеру телефона и СМС-коду подтверждения/коду из пуш-уведомления.<br>**Аккаунты:** используются заранее зарегистрированные и активные аккаунты.<br>**Тарифы:** должен быть подготовлен один аккаунт с активной подпиской и один аккаунт без подписки.<br>**Ошибочный код:** при вводе неправильного кода сервис показывает ошибку, не выполняет вход и позволяет повторить ввод.<br>**Корректный код:** после ввода правильного кода пользователь попадает в свой аккаунт.<br>**Отсутствие кода по истечении времени:** если пользователю не приходит СМС-код, пользователь должен иметь возможность запросить повторную отправку.<br>**Канал доставки:** канал получения кода подтверждения не фиксируется. | **Must** |
| **BR-002** | **Персональные рекомендации** | **Главная страница:** после авторизации пользователь видит персональные музыкальные рекомендации.<br>**Подборки:** пользователь может открыть рекомендованную подборку.<br>**Воспроизведение:** пользователь может запустить воспроизведение музыки из подборки.<br>**Сохранение:** трек можно добавить в «Мою музыку» или пользовательский плейлист.<br>**Тарифные различия:** для пользователя без подписки конкретный воспроизводимый трек может определяться сервисом. | **Must** |
| **BR-003** | **Поиск музыки** | **Объекты поиска:** треки, исполнители и альбомы.<br>**Результаты:** сервис показывает релевантные результаты поиска.<br>**Пользователь с подпиской:** может открыть и воспроизвести конкретный найденный трек.<br>**Пользователь без подписки:** может пользоваться поиском, но не может открыть и запустить конкретный найденный трек.<br>**Переходы:** из поиска можно перейти на страницу исполнителя или альбома. | **Must** |
| **BR-004** | **Страницы исполнителей и альбомов** | **Страница исполнителя:** отображаются исполнитель, популярные треки и альбомы.<br>**Страница альбома:** отображаются обложка, название и список треков.<br>**Подписка на исполнителя:** пользователь может добавить исполнителя в избранное и получать информацию о новых треках.<br>**Пользователь с подпиской:** может открывать и воспроизводить доступный контент.<br>**Пользователь без подписки:** видит полный контент страниц, но воспроизведение ограничено условиями тарифа.<br>**Сохранение:** треки можно добавлять в «Мою музыку» и плейлисты. | **Must** |
| **BR-005** | **Управление воспроизведением** | **Основные действия:** запуск, пауза, продолжение, переход к следующему и предыдущему треку.<br>**Дополнительные действия:** перемотка, изменение громкости, повтор и случайный порядок.<br>**Плеер:** отображает название трека, исполнителя, обложку, длительность и текущую позицию, очередь треков.<br>**Обновление:** при смене трека информация в плеере обновляется.<br>**Пользователь без подписки:** количество пропусков треков ограничено, точное значение не задаётся.<br>**Достижение лимита:** поведение после достижения лимита пропусков не определено. | **Must** |
| **BR-006** | **Раздел «Любимое»** | **Добавление:** пользователь может сохранять треки из рекомендаций, поиска, страницы исполнителя, альбома и плеера.<br>**Доступность:** сохранённые треки отображаются в разделе «Любимое».<br>**Совместное использование:** один трек может быть одновременно сохранён в «Любимом» и в плейлистах.<br>**Сохранение между сессиями:** доступно для пользователей с подпиской и без неё. | **Must** |
| **BR-007** | **Создание и редактирование плейлистов из раздела «Коллекции»** | **Создание:** пользователь может создавать несколько плейлистов.<br>**Название:** при создании указывается название плейлиста.<br>**Добавление:** треки можно добавлять из рекомендаций, поиска, страниц исполнителей и альбомов, добавленных и любимых треков.<br>**Разные способы:** добавление может выполняться через кнопку, меню трека или другой доступный элемент.<br>**Редактирование:** пользователь может изменить название, добавить и удалить трек.<br>**Порядок треков:** может изменяться, если такая функция поддерживается.<br>**Сохранение:** плейлисты и их состав сохраняются между сессиями для обоих типов пользователей.<br>**Дубли:** поведение при повторном добавлении одного трека в тот же плейлист не определено.<br>**Бесплатный тариф:** ограничения работы с плейлистами для пользователя без подписки не определены. | **Must** |
| **BR-008** | **Очередь воспроизведения** | **Формирование:** пользователь может добавлять в очередь треки из разных разделов.<br>**Порядок:** очередь определяет последовательность последующего воспроизведения.<br>**Обновление:** после завершения или ручного переключения трека очередь обновляется.<br>**Изменение порядка:** поддерживается, если такая функция доступна.<br>**Пользователь с подпиской:** очередь сохраняется между выходом и повторным входом.<br>**Пользователь без подписки:** сохранение очереди между сессиями не требуется. | **Should** |
| **BR-009** | **Выход из аккаунта** | **Завершение сессии:** пользователь может выйти во время использования сервиса.<br>**Персональные данные:** после выхода библиотека, плейлисты и другие персональные данные не отображаются.<br>**Авторизация:** пользователь считается неавторизованным.<br>**Публичная версия:** после выхода отображается публичная или стартовая версия сервиса. | **Must** |
| **BR-010** | **Повторная авторизация и восстановление состояния** | **Повторный вход:** пользователь входит по тому же номеру телефона.<br>**Аккаунт:** после входа открывается тот же аккаунт.<br>**Для обоих тарифов:** восстанавливаются «Моя музыка», плейлисты и история прослушивания.<br>**Для подписки:** дополнительно восстанавливаются очередь, текущий трек и позиция воспроизведения.<br>**Для бесплатного тарифа:** очередь, текущий трек и позиция между сессиями не сохраняются.<br>**Целевое изменение:** улучшить надёжность восстановления пользовательского состояния после повторного входа. | **Must** для библиотеки, плейлистов и истории; **Should** для очереди и позиции |
| **BR-011** | **Тарифные ограничения** | **Пользователь с подпиской:** получает полный доступ к описанным функциям.<br>**Пользователь без подписки:**<br>- Воспроизведение осуществляется преимущественно через подборки<br>- Количество переключений треков ограничено<br>- Наличие рекламы является ограничением бесплатного тарифа, но не включается в основной e2e-сценарий<br>- Нельзя открыть и запустить конкретный найденный трек<br>- Полный контент доступен для просмотра, но воспроизведение ограничено тарифом | **Must** |
