# E2E Journey / Suite Plan

## Общая информация

- **ID journey:** J02-free-restore-cycle
- **Название:** Сквозной цикл Free: авторизация → поиск (ограниченный) → воспроизведение через подборки с лимитом пропусков → сохранение в «Любимое» → выход → повторный вход без очереди и текущего трека
- **Цель journey:** подтвердить, что пользователь бесплатного тарифа проходит P0-02 полностью — успешно входит по СМС-коду, видит персональные рекомендации, ограничен в поиске конкретного трека, потребляет музыку из подборок, упирается в лимит пропусков с описанным UI-поведением, после выхода и повторного входа получает только библиотеку, плейлисты и историю.
- **Приоритет:** Критический
- **Функциональные области:** Авторизация · Рекомендации · Поиск · Управление воспроизведением · Раздел «Любимое» · Тарифные ограничения · Выход/повторный вход
- **Покрываемые требования:** REQ-07, REQ-12, P0-02, BR-001, BR-002, BR-003, BR-005, BR-006, BR-009, BR-010, BR-011, BR-013, BR-016

## Начальное состояние

- **Аккаунт:** заранее зарегистрированный пользователь без активной подписки; номер телефона известен тесту, канал доставки кода выбран на этапе прогона (см. Q-J02-03).
- **Авторизация:** сессия отсутствует; открыта публичная/стартовая страница сервиса.
- **Данные пользователя:** «Моя музыка» — пусто; пользовательских плейлистов нет; очередь пуста; история прослушивания пуста.
- **Устройство / сеть:** стационарный браузер, стабильное интернет-соединение.

## Основной путь

Пользователь Free на публичной странице вводит номер телефона, получает СМС-код, после подтверждения попадает на главный экран с персональными рекомендациями. Переходит в поиск, находит нужный трек в результатах, кликает по нему — сервис не запускает воспроизведение (UI-реакция по пробелу G-J02-01). Возвращается на главную, открывает одну из рекомендованных подборок, запускает первый трек подборки. Ставит трек на паузу и сохраняет в «Любимое», счётчик коллекции становится равным 1. Несколько раз подряд нажимает «Далее» до упора в лимит пропусков; дальнейшие нажатия не переключают трек. Выходит из аккаунта — плеер сбрасывается, персональные разделы скрыты. Входит заново по тому же номеру и видит «Любимое», плейлисты и историю восстановленными, а плеер/очередь/позицию — сброшенными. Этот поток становится кейсом `TC-J02-00`.

## Зависимости и риски

- Точное число разрешённых пропусков для Free BR-005 не задаёт («точное значение не задаётся»), поэтому этап 7 зависит от ответа продукта (G-J02-02, Q-J02-01). Без числа шаг «исчерпать лимит» физически не выполняется.
- Реакция UI на попытку воспроизвести конкретный трек из поиска (этап 4) не описана — есть только запрет (BR-011); варианты поведения покрывает пробел G-J02-01 и вопрос Q-J02-02.
- AS-02 говорит, что «сетевые сбои не входят в сценарий», тогда как этапы 5–7 завязаны на стабильную сеть для переключения треков. Если канал пропускает длинные ответы, тест будет флапать.
- RS-01 фиксирует риск «различия поведения между тарифами могут быть описаны неполно» — этот journey именно про эти различия и потому принимает риск на себя.

## Выявленные пробелы

- **G-J02-01.** BR-011 запрещает Free-пользователю запускать конкретный найденный трек, но не описывает, что именно отображается на UI: всплывающее сообщение, серое состояние элемента, перенаправление на экран подписки. Цитата: *«Нельзя открыть и запустить конкретный найденный трек»*. Без ответа этап 4 не имеет наблюдаемого результата, кроме «не играет».
- **G-J02-02.** BR-005 фиксирует лимит пропусков без указания числа (*«точное значение не задаётся»*); BR-013 прямо пишет *«Поведение не определено в требованиях — требуется фактическая проверка UI»*. Цитата: *«Достижение лимита: поведение после достижения лимита пропусков не определено»*. Без числа этап 7 превращается в исследовательский прогон.
- **G-J02-03.** После достижения лимита пропусков BR-005/BR-013 вместе не уточняют, что видит пользователь: заблокирована ли кнопка «Далее», показано ли сообщение, либо треки продолжают играть до конца текущего. Цитата: *«Блокируется ли переключение треков после лимита — требует фактической проверки UI»*.
- **G-J02-04.** BR-008 говорит, что для Free-тарифа «сохранение очереди между сессиями не требуется», однако это формулировка допускает два прочтения: «очередь живёт только в рамках сессии и сбрасывается при logout» или «очередь формируется, но сервер её не сохраняет». Цитата: *«Пользователь без подписки: сохранение очереди между сессиями не требуется»*. Этап 8 проверяет, что после повторного входа очередь пуста — обе трактовки удовлетворяют этому, но различимы они только если в продукте появится индикатор «очередь восстановлена».

## Уточняющие вопросы

1. **Q-J02-01** — Каково фактическое числовое значение лимита пропусков для Free-аккаунта за сессию? Без числа нельзя детерминированно выполнить этап 7. Severity: blocking.
2. **Q-J02-02** — Что именно отображается на UI при попытке воспроизвести конкретный найденный трек Free-пользователем (этап 4)? Модальное сообщение с текстом, неактивная карточка, перенаправление. Блокирует ожидаемый результат шага в `TC-J02-00`. Severity: blocking.
3. **Q-J02-03** — Какой канал доставки СМС-кода использовать для Free-аккаунта в e2e-прогоне, учитывая, что BR-001 канал не фиксирует? Блокирует воспроизводимость этапов 1–2. Severity: blocking.
4. **Q-J02-04** — Когда именно сгорает лимит пропусков: при каждой смене трека через «Далее», или засчитывается также автоматический переход в конце трека? Блокирует детерминированный шаг «исчерпать лимит» в `TC-J02-00`. Severity: advisory.
5. **Q-J02-05** — Показывается ли где-либо пользователю Free индикатор «N пропусков из M использовано», или лимит — внутренняя механика без UI? Блокирует формулировку наблюдаемого результата этапа 7. Severity: advisory.
