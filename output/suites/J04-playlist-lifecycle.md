# E2E Journey / Suite Plan

## Общая информация

- **ID journey:** J04-playlist-lifecycle
- **Название:** Жизненный цикл пользовательского плейлиста: создание с именем, добавление треков из поиска и из плеера, перестановка/удаление, сохранение между сессиями
- **Цель journey:** подтвердить REQ-08…REQ-10 + BR-007 + REQ-14: пользователь Premium создаёт плейлист в «Коллекции», пополняет его из разных источников (поиск, плеер), редактирует состав (переставляет, удаляет), выходит и заново входит — плейлист восстанавливается вместе с составом.
- **Приоритет:** Высокий
- **Функциональные области:** Авторизация · Поиск · Управление воспроизведением · Плейлисты («Коллекция») · Выход/повторный вход
- **Покрываемые требования:** REQ-08, REQ-09, REQ-10, REQ-14, BR-001, BR-003, BR-005, BR-007, BR-009, BR-010

## Начальное состояние

- **Аккаунт:** заранее зарегистрированный Premium-пользователь; номер телефона известен тесту.
- **Авторизация:** сессия отсутствует; открыта публичная/стартовая страница.
- **Данные пользователя:** «Любимое» — пусто; пользовательских плейлистов нет; очередь пуста.
- **Устройство / сеть:** стационарный браузер, стабильное интернет-соединение.
- **Каталог:** в каталоге есть как минимум четыре разных трека (`{ТрекSearchAdd}`, `{ТрекPlayerAdd}`, `{ТрекReorderUp}`, `{ТрекRemove}`), пригодных для добавления в плейлист.

## Основной путь

Пользователь Premium входит по СМС-коду, переходит в «Коллекции» → «Плейлисты». Создаёт приватный плейлист «Road Trip Mix». Через поиск добавляет в него первый трек, затем запускает второй трек и добавляет его уже из плеера. Проигрывает плейлист, добавляет ещё два трека, переставляет один из них выше вручную и удаляет четвёртый. Переименовывает плейлист в «Road Trip Mix · v2». Выходит из аккаунта и снова входит по тому же номеру — находит плейлист с тем же именем, составом и порядком. Этот поток становится кейсом `TC-J04-00`.

## Зависимости и риски

- REQ-08 ограничивает имя до 100 символов, но не описывает, как именно UI сообщает о превышении (см. G-J04-01). Этап 7 использует имя гарантированно в пределах лимита, чтобы не зависеть от этого пробела.
- BR-007 явно говорит «Порядок треков: может изменяться, если такая функция поддерживается» — наличие UI drag-to-reorder не гарантировано. Если reorder отсутствует, этап 6 нужно переписать как удаление двух треков вместо перестановки. Это блокирующий пробел (G-J04-03).
- REQ-10 «отсортированы по дате последнего изменения» без указания направления (G-J04-02). Тест на этапе 8 сверяет только состав плейлиста, не его место в списке.
- RS-03 (каталог может меняться) — все тестовые треки должны существовать на момент прогона.
- AS-02 — стабильная сеть обязательна для всех сетевых операций, иначе плеер «застрянет» на середине этапа 5.

## Выявленные пробелы

- **G-J04-01.** REQ-08 фиксирует верхнюю границу имени (100 символов), но не описывает реакцию UI на превышение: ошибка валидации, молчаливая обрезка, блок ввода, красная рамка. Цитата: *«Длина названия — до 100 символов»*. Без ответа этап 7 вынужден либо использовать безопасное имя, либо делать поведение предметом проверки.
- **G-J04-02.** REQ-10 говорит «отсортированы по дате последнего изменения», но не указывает направление (ASC/DESC) и не определяет, что считать «последним изменением» — создание, переименование, добавление трека, изменение порядка. Цитата: *«отсортированы по дате последнего изменения»*.
- **G-J04-03.** BR-007 пишет *«Порядок треков: может изменяться, если такая функция поддерживается»* — это допускает реализацию без drag-to-reorder, и тогда часть шагов этапа 6 не имеет UI. Цитата дословная.
- **G-J04-04.** BR-007 отмечает: *«Бесплатный тариф: ограничения работы с плейлистами для пользователя без подписки не определены»* — отдельная формулировка, которая делает поведение Free-плейлистов непредсказуемым.

## Уточняющие вопросы

1. **Q-J04-01** — Какова UX-реакция на ввод имени плейлиста длиннее 100 символов? Сообщение об ошибке, жёсткий лимит ввода, серверная ошибка при сохранении. Блокирует наблюдаемый результат варианта TC-J04-01. Severity: blocking.
2. **Q-J04-02** — В каком направлении сортируется список «Моя коллекция» → «Плейлисты»: самые свежие сверху (DESC) или снизу (ASC)? Блокирует ожидаемое положение «Road Trip Mix · v2» в списке после этапа 8. Severity: advisory.
3. **Q-J04-03** — Поддерживается ли в текущей реализации drag-to-reorder для треков внутри плейлиста? Если нет — каким жестом/API пользователь меняет порядок. Блокирует детерминизм этапа 6 в `TC-J04-00`. Severity: blocking.
4. **Q-J04-04** — Какие именно поля участвуют в «дате последнего изменения» плейлиста (REQ-10): создание, переименование, добавление/удаление трека, перестановка? Блокирует трактовку того, когда именно плейлист «свежее» другого. Severity: advisory.
