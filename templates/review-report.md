# Отчёт критика — J<NN>, итерация <N>

## Сводка

| Показатель | Значение |
|---|---|
| Journey | J<NN>-<slug> |
| Итерация | <N> |
| Кейсов в journey | <n> |
| Переревьюено на этой итерации | <n> |
| Findings перенесено с итерации <N-1> | <n> |
| BLOCKER | <n> |
| MAJOR | <n> |
| MINOR | <n> |

`BLOCKER` / `MAJOR` / `MINOR` считают **все** находки journey, включая перенесённые:
это те же числа, что уйдут в `output/state/<JOURNEY_ID>.json`. Уменьшить их потому, что кейс
не перечитывали, нельзя — тогда суженный объём ревью превращается в тихую потерю находок.

## Результат линтера

`scripts/validate_cases.py` — <exit code>, findings: <n>. Линтер всегда идёт по всем кейсам.

## Объём этой итерации

Из `scripts/review_scope.py` (на первой итерации — «полное ревью»):

| Кейс | Объём |
|---|---|
| TC-J<NN>-00 | переревьюен / перенесён — <причина из perCase> |

## Трассируемость

| REQ | Проверяется в | Статус |
|---|---|---|
| REQ-01 | TC-J01-00, шаг 3 | покрыто |
| REQ-07 | — | не покрыто (MAJOR #<n>) |

Ожидаемые результаты без требования:

| Кейс, шаг | Утверждение | Есть в пробелах? | Вывод |
|---|---|---|---|

## Находки

```
#1 [BLOCKER] <кейс>, шаг <N> — <тип нарушения>
Что не так: …
Почему: … (проверено REQ-…)
Исправить: …
```

Находка по кейсу, который на этой итерации не перечитывали, **переносится дословно** — тот же
номер, тот же текст — с пометкой в первой строке:

```
#3 [MAJOR] <кейс>, шаг <N> — <тип нарушения>  (перенесено с итерации <N-1>)
```

Молча исчезнувшая находка — единственный отказ, которого суженное ревью допустить не может.
